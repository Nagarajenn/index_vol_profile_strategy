# Trading Intelligence Dashboard -- Backend (FastAPI)

Read-only presentation layer over the existing ingestion pipeline's Postgres
tables. This service never writes to the database -- the live loop / backfill
pipeline (`../pipeline/`, `../db/`) remains the sole writer.

## Setup

```
py -3.14 -m venv venv
venv\Scripts\pip install -r requirements.txt
```

From the **project root** (not `backend/`), install the shared `analytics`/
`config` packages as an editable dependency into this venv:
```
backend\venv\Scripts\pip install -e .
```
This is what lets `app/services/dashboard_service.py` reuse
`analytics.resample.resample_to_interval` and `config.settings` without
duplicating that logic. It reads the same root `.env` as the pipeline
(`DATABASE_URL`, `DB_SCHEMA`) -- there is only one `.env` for the whole
project.

## Database: schema ownership and Alembic

**`db/schema.sql` (the pipeline's own DDL) is authoritative for table
creation.** Alembic in this backend only owns *future* schema deltas, and
must never be used to create the initial tables.

Setup order for a fresh database:
1. `python ..\db\setup_db.py` (from the project root, using the pipeline's
   own venv) -- creates the 5 tables per `db/schema.sql`.
2. `venv\Scripts\python -m alembic stamp head` (from `backend/`) -- marks
   Alembic's baseline migration as applied *without running any DDL*. The
   baseline migration (`alembic/versions/..._baseline.py`) has zero
   operations by design -- it was generated by autogenerating against the
   already-correct live schema until the diff came back empty, not by
   hand-authoring `CREATE TABLE` statements.

Never run `alembic upgrade head` on a fresh database expecting it to create
tables -- it won't (the baseline is empty), and schema creation stays
`db/setup_db.py`'s job.

Adding a real schema change later (e.g. a new table for future
watchlists/alerts features): update the SQLAlchemy models in `app/models/`,
then `alembic revision --autogenerate -m "..."`, review the generated
migration, `alembic upgrade head`.

## Running

```
venv\Scripts\uvicorn app.main:app --reload --port 8000
```
