How the DDL was validated before it was applied (approval item 7).
  1. Static guard (hr_capture/schema_guard.py): every statement must be CREATE TABLE IF NOT EXISTS hr_* or CREATE [UNIQUE] INDEX IF NOT EXISTS hr_* ON hr_*. It rejects ALTER, DROP, TRUNCATE, all DML, GRANT/REVOKE, foreign keys, views, functions, triggers, schemas and extensions. Result: PASS, 0 violations.
  2. No overlap with any table created by db/schema.sql, and no reference to any existing table (comments stripped).
  3. Applied with a before/after structure snapshot of every pre-existing table: digest d40188e5… before = after; the script would have exited non-zero on any difference. The same digest was also computed independently before any HR code was written.
  4. A separate Postgres schema was not possible (the role lacks CREATE on the database), so the hr_ prefix inside ai_poc_strategy follows the existing paper_/cas_/mti_ convention.
  5. Real-write self-test: a synthetic session (dated 2000-01-03) wrote to all 7 tables — 1,202 raw ticks, 10,080 bars, 9,240 option rows, 420 state rows — with 0 failures and 0 spills. It verified BYTEA (162-byte packets), JSONB depth and summary, and the session finalisation. It was then deleted, leaving 0 rows in every hr_ table.

10. Connectivity test (approval item 29) and what it changed

Experiment (2026-09-13, outside market hours)Result
Universe resolution from Friday's last option chainOK 48 instruments, no issues. NIFTY band ATM 23,450 (spot 23,435.10, expiry 09-15, future 68407 Sep29); SENSEX band ATM 74,800 (spot 74,781.76, expiry 09-17, future 844615 Sep24); index IDs 13 / 51 from scrip master
HR client, 48 instrumentsHandshake accepted, subscribed, closed in ~10 ms without a close frame, zero packets; after rapid retries the handshake returned HTTP 429
Spaced diagnostic: one ticker, compression off / defaultConnected, closed after 0.177 s / 0.194 s, zero packets
Dhan SDK MarketFeed, 3 instruments (reference)Connected, closed after 0.172 s, zero packets — identical
Server disconnect codes (805–809) receivedNone
What it proved and what it did not. Proven: credentials authenticate on the feed host, the 48-instrument universe resolves with no hard-coded values, subscription messages match the SDK's, and HR's client behaves exactly like the reference client. Not proven: that data flows. The immediate close happens with the SDK too, so it is server behaviour — most likely out-of-hours, but an account entitlement problem cannot be excluded without a market-hours connection.
Three defects found and fixed because of this test.
  1. HTTP 429 was retried after 1–2 s. Now: rate-limit cool-down of 60 → 120 → 300 s.
  2. The backoff reset as soon as a subscription was sent, so an immediately-closing server became a 1-second reconnect loop (which is what produced the 429). Now the backoff resets only after data arrives or the connection stays up 30 s.
  3. No stop condition for a server that accepts and immediately drops. Now: after 5 consecutive immediate closes with zero packets, the session ends as FAILED_CONNECTION. This bounds worst-case feed traffic on Tuesday to about 5 connections in roughly 15 seconds.
Each fix has a regression test.

14. Known limitations (disclosed, not fixed)

  • Live data flow is unproven until Tuesday (§10).
  • Shared resources code cannot isolate: the same Postgres instance (mitigated by 2 s batching, 5 s statement / 2 s lock timeouts, spill-to-file) and the same Dhan credentials (an expired token stops both systems regardless).
  • Exchange time is 1-second resolution; no sub-second exchange ordering is claimed. Bucketing uses receive time.
  • trade_count is a lower bound (the feed sends snapshots, not a trade tape).
  • The ATM band is fixed at 14:54; a large move is recorded as a BAND_EDGE event, not followed.
  • Not available from the feed: IV/Greeks, the auction indicative price, 20-level depth for BSE (SENSEX) contracts, and any historical 5 s data.
  • Market-state thresholds (30 s stale/frozen) are initial descriptive defaults, not tuned on data.
